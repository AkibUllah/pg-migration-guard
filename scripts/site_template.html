Each statement ran on a 2,000-row table inside a transaction that was rolled back. After it ran, the tool read pg_locks for the lock held, compared filenodes for a rewrite, and read the sequential scan counter. A second connection with a 100 ms lock_timeout then tried a real read and a real write, so "blocks" means traffic was actually stopped.

What the linter recommends instead

The fixes are measured the same way. NOT VALID followed by VALIDATE does the scan under a lock that lets traffic through, which is the point of the two-step pattern.

A safe statement can still say "blocks" here. What matters is how long: with no rewrite and no scan, it only changes the catalog and holds its lock for milliseconds, as long as it gets the lock quickly. That is why the linter also asks for a lock_timeout.
